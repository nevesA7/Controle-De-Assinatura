# ADR-001 — Por que usar PostgreSQL gerenciado na Aiven

- **Status:** aceito
- **Data:** 17/11/2026
- **Equipe:** equipe-XX (preencher com os nomes do grupo)

## Contexto
Nosso app de controle de assinaturas precisa guardar os dados de forma
confiável, mesmo se a aplicação reiniciar. A equipe tem poucas semanas, ninguém
é administrador de banco e a faculdade não deixa instalar nada no computador.
Tudo precisa ser criado pelo navegador, com Terraform rodando no GitHub Actions,
e usando só planos gratuitos.

## Decisão
Usar um serviço PostgreSQL gerenciado na Aiven, criado por Terraform.

## Alternativas consideradas

| Alternativa | Vantagens | Desvantagens |
|---|---|---|
| PostgreSQL gerenciado na Aiven (escolhida) | Plano gratuito sem cartão; a Aiven cuida de instalação, atualização e backup; tem provider oficial no Terraform, então o banco vira código | Serviço gratuito pode ser desligado por inatividade; poucos recursos; dependemos da Aiven |
| PostgreSQL instalado e mantido pela equipe em uma VM | Controle total da configuração; aprende-se mais sobre administração | VM de nuvem costuma pedir cartão; a equipe teria que cuidar de patches, backup e segurança; não dá para instalar nada localmente |
| Outro serviço gerenciado de nuvem pública (ex.: RDS na AWS) | Muito completo e usado no mercado | Pede cartão de crédito e pode gerar cobrança; configuração bem mais complexa para o tamanho do projeto |
| SQLite dentro do app | Zero configuração | O disco do Render gratuito é apagado a cada deploy, então os dados somem; não treina infraestrutura como código |

## Consequências
- **Fica mais fácil:** criar e destruir o banco só com `terraform apply` e
  `terraform destroy`; não precisamos fazer backup nem atualizar o PostgreSQL
  na mão; qualquer pessoa reproduz o ambiente a partir do repositório.
- **Fica mais difícil:** dependemos de uma empresa externa e dos limites do
  plano gratuito (pouca memória e armazenamento).
- **Riscos aceitos:** a Aiven pode desligar o serviço gratuito por inatividade.
  Para reduzir o risco, vamos conferir o banco antes da demonstração e religar
  no console se for preciso. O `/healthz` mostra rápido se o banco caiu.
